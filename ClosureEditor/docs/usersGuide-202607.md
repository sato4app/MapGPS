# ClosureEditor 利用者の手引（通行止め・通行困難地点の登録と公開）

**バージョン:** 1.0
**最終更新日:** 2026年7月28日
**対象:** 運用担当者（通行止め情報を登録・公開する人）
**関連:**
[機能仕様 `funcspec-202607.md`](funcspec-202607.md) /
[データ仕様 `dataspec-202607.md`](dataspec-202607.md)

---

## 1. この手引について

ハイキングマップに表示する「通行止め・通行困難地点」を**追加・修正・解除**し、
ユーザー（minoh-hiking の利用者）へ**公開**するための手順をまとめたものです。

**位置指定から公開まで、このアプリ1つで完結します。**
以前のように MapEditor で作ったファイルを minoh-hiking へ持ち込む必要はありません。

> 公開が失敗したときの**原因の見分け方（エラーコード E01〜E05）と対応**は
> [9章](#9-公開に失敗したときの対応エラーコード別)にまとめています。

---

## 2. 事前準備

| 準備するもの | 内容 |
|--------------|------|
| **アプリのURL** | MapGPS のカードから開きます（直接開く場合は `https://sato4app.github.io/ClosureEditor/`）。**PC のブラウザ**で使ってください |
| **公開トークン** | 公開時に必要な秘密の文字列。運用担当者だけが知っておきます（決め方・設定方法は [10章](#10-付録-公開トークンの決め方と-vercel-設定設定担当者向け)） |
| **前回の geojson**（任意） | 前回出力した `Closure-*.geojson`。続きから編集する場合に読み込みます |
| **ハイキングマップの geojson**（任意） | 緊急ポイント・ルート／スポットのファイル。位置を決める目印として背景に表示できます |

> 公開トークンは**初回の「公開」時に一度だけ入力**します。以降はその端末に保存され、
> 再入力は不要です（端末を変えた場合や、間違えた場合は再入力になります → [8章](#8-公開トークンについて)）。

---

## 3. 画面の見方

地図の右上に操作パネルが表示されます。上から3つのブロックに分かれています。

| ブロック | 用途 |
|----------|------|
| **ハイキングマップ（背景）** | 目印として地図に重ねるだけ。編集・出力・公開の対象にはなりません |
| **登録地点** | 通行止め・通行困難地点の読み込み／追加・移動・削除／属性編集／ファイル出力 |
| **公開** | バージョンの入力、現在公開中の確認、ユーザーへの公開 |

パネル右上の日付は**アプリの版**です（データのバージョンではありません）。

---

## 4. 更新の全体フロー

```
現場からの報告
     │
     ▼
 ① ハイキングマップ（背景）を読み込む         ※任意・目印用
 ② 前回の geojson を読み込む                  ※続きから編集する場合
 ③ 地図をクリックして地点を追加／ドラッグで移動／削除
 ④ 区分・登録理由・備考を編集（標高は自動取得）
 ⑤ ファイル出力 … 手元の控えとして保存
 ⑥ バージョンを入力して「公開」 → ユーザーへ即時公開
     │
     ▼
 ⑦ minoh-hiking の地図で公開結果を確認
```

**公開は「全置換」です。** 前回分への追記ではなく、送ったデータで丸ごと置き換わります。
そのため**公開時は、残したい地点もすべて画面に載っている**必要があります。

## 5. 手順（通常の更新）

### 手順1. 背景（ハイキングマップ）を表示する ※任意

「ハイキングマップ（背景）」の **「ファイル読み込み」** で geojson を選びます
（複数まとめて選べます）。ルート・ポイントが地図に重なり、位置を決める目印になります。

- 「地図に表示」のチェックで表示・非表示を切り替えられます。
- 「消去」で取り除けます。
- 背景はクリックに反応しません（背景の上をクリックしても地点を追加できます）。

### 手順2. 前回のデータを読み込む ※続きから編集する場合

「登録地点」の **「ファイル読み込み」** で前回の `Closure-*.geojson` を選びます。
読み込んだ件数がメッセージで表示され、地点が地図とドロップダウンに並びます。

- **同じ `id` の地点はスキップ**されます（重複件数を通知します）。
- バージョン入力欄が空のときは、ファイルのバージョンが自動で入ります。
  すでに入力済みの場合は上書きしません（意図しない巻き戻しの防止）。
- 現在公開中のデータから編集を再開したい場合は、`https://minoh-hiking.vercel.app/api/closures`
  をブラウザで開いて保存したファイルも読み込めます。

### 手順3. 地点を追加・移動・削除する

**「追加・移動」ボタン**を押すとモードに入ります（ボタンが強調表示され、カーソルが十字になります）。

| やりたいこと | 操作 |
|--------------|------|
| 地点を追加 | **地図をクリック**します。`地点1` などの名前で追加され、標高が自動取得されます |
| 地点を移動 | マーカーを**ドラッグ**します。離した位置で標高を再取得します |
| モードを抜ける | 「追加・移動」ボタンをもう一度押します |
| 地点を削除 | ドロップダウンか地図で地点を選び、**「削除」**を押します（確認ダイアログが出ます） |

> **モード中は地図クリックが「地点の追加」になります。** 地図を動かすだけのつもりで
> クリックすると地点が増えるので、編集が終わったらモードを抜けてください。

### 手順4. 地点の内容を編集する

ドロップダウン、または地図のマーカーをクリックして地点を選ぶと、
選択中のマーカーが**アクア色**になり、内容が入力欄に表示されます。

| 項目 | 内容 |
|------|------|
| 選択地点 | 地点名（例「風呂谷 倒木」）。空欄にはできません |
| 備考 | 補足（例「巻き道あり」） |
| 区分 | **通行止め**（赤い✖）／**通行困難**（橙の三角）。ユーザーの地図でも同じ見た目になります |
| 登録理由 | 工事／倒木／落石／なし |

- 名称・備考は**入力欄から離れたとき**に、区分・登録理由は**選んだとき**に反映されます。
- 変更すると地点の更新日が本日に変わり、ポップアップの内容も更新されます。
- 区分を選んでいない地点は `?` マークで表示されます。**未選択のまま公開すると、
  ユーザーには通行止めとして見えます**ので、公開前に区分を決めてください。

### 手順5. ファイル出力（手元の控え）

「登録地点」の **「ファイル出力」** を押すと `Closure-20260728_C3_D2.geojson`
（C=通行止め件数 / D=通行困難件数）の形式で保存できます。

次回この続きから編集するために、**公開の前に控えを保存しておくことをおすすめします。**
区分が未選択の地点がある場合やバージョンが未入力の場合は、出力後に警告が出ます
（出力自体は行われます）。

### 手順6. バージョンを入力して「公開」

1. 「公開」の **「バージョン」** に新しい値を入力します（例 `2026-07-28.1` → [7章](#7-バージョンの付け方)）。
2. **「公開」** を押します。確認ダイアログに**現在公開中**と**これから公開**が並んで出ます。

   ```
   通行止め・通行困難地点をユーザーへ公開します。

   現在公開中: 2026-07-16.1（12件）
   これから公開: 2026-07-28.1（14件）

   よろしいですか？
   ```

   **古いファイルから公開しようとしていないか、ここで必ず確認してください。**
   バージョンと件数に見覚えがなければキャンセルします。
3. **OK** を押します。**初回のみ**公開トークンの入力を求められます。
4. 成功すると「バージョン … をユーザーへ公開しました」と表示されます。

### 手順7. 公開結果を確認する

minoh-hiking の地図を**開き直して**、地点の位置・種別・件数を確認します。
誤りがあれば ClosureEditor で直し、**新しいバージョンで再公開**します。

- ユーザーの端末には、**次回マップを開いたとき**に反映されます。
- 「現在公開中」欄の **↻** ボタンで、公開中のバージョンと件数を再取得できます。

## 6. 地点の解除（削除）・全解除

公開は**全置換**です（送ったデータで丸ごと置き換え）。

- **一部の地点を解除したい** → その地点を「削除」してから、新しいバージョンで公開します。
- **すべて解除したい** → 全地点を削除し、0件の状態で公開します。
  - このとき確認ダイアログに **「【注意】0件のため、公開中の全地点が地図から消えます。」**
    が追記されます。意図どおりなら OK します。

> 解除も「公開」操作で行います。別途の解除操作はありません。
> **残したい地点を画面から消したまま公開しないでください**（公開データから消えます）。

---

## 7. バージョンの付け方

- **更新のたびに必ず新しい値に変える**必要があります。バージョンは各端末の
  「新しいデータが来た」判定に使われ、**同じ値だと更新に気づけません**。
- 推奨形式は **`日付.連番`**（例 `2026-07-28.1`、同日中の2回目なら `2026-07-28.2`）。
- **未入力のままでは公開できません**（サーバー側で E03 になります）。
- ファイル出力にも同じバージョンが書き込まれるため、読み込み直せば同じ状態から再開できます。

---

## 8. 公開トークンについて

- 公開トークンは、公開先サーバー（Vercel）の環境変数 `CLOSURES_PUBLISH_TOKEN` と**同じ値**です。
- **初回の「公開」時に一度入力**すると、**その端末**に保存され、以降は再入力不要です。
- **アプリのコードには埋め込まれていません**（運用担当者だけが知っている前提）。
- トークンが違うと **「【E01】公開トークンが正しくありません」** と表示され、保存が消えます。
  もう一度「公開」を押して正しい値を入力してください。
- 別の端末で公開するときは、その端末で改めて入力が必要です。
- **共用の端末を離れるときは「トークン消去」ボタン**で保存済みトークンを消してください。

## 9. 公開に失敗したときの対応（エラーコード別）

「公開」に失敗すると、**エラーコード（E01〜E05）付きのメッセージ**が出ます。
運用担当者は、**表示されたコードと文面をそのまま開発担当者に伝えれば**原因を切り分けられます。
まず自分で試せることを行い、直らなければ開発担当者へ連絡してください。

### 9.1 コード早見表

| コード | 画面の要点 | 主な原因 | まず試すこと | 開発担当者の対応（サーバー側） |
|--------|-----------|----------|--------------|----------------------------|
| **E01** | 公開トークンが正しくありません | 入力したトークンが違う | もう一度「公開」→ 正しいトークンを入力（→ [8章](#8-公開トークンについて)） | 正しい `CLOSURES_PUBLISH_TOKEN` を伝える／必要ならローテーション（→ [10.3](#103-トークンのローテーション更新)） |
| **E02** | 公開機能が設定されていません | サーバーに公開トークンが未設定、または設定後に未反映 | （操作では直らない）開発担当者へ連絡 | `CLOSURES_PUBLISH_TOKEN` を設定し**再デプロイ**（→ [10.2](#102-vercel-での設定)） |
| **E03** | 公開データに不備があります | 送信データの中身が不正 | 表示の「理由」を見て直し、再公開（→ 下記 9.2） | 通常は不要（データ側の問題） |
| **E04** | 公開データの保存に失敗しました | 公開ストア（Blob）への保存失敗 | 少し時間をおいて再試行 | Blob 接続と `BLOB_READ_WRITE_TOKEN` を確認して**再デプロイ**、Runtime Logs で生エラー確認 |
| **E05** | サーバーに接続できません（通信エラー） | 通信断・接続不良・サーバー障害 | 通信状況を確認して再試行 | Vercel の稼働・`/api/closures` の到達性を確認 |

> 失敗時に「今回のデータをこの端末に保存しますか?」と出たら、**保存しておくと安全**です。
> あとで公開をやり直せるほか、開発担当者に渡して調べてもらえます。

### 9.2 E03（データ不備）の代表例と直し方

E03 は**トークンではなくデータの中身**の問題です。画面の「理由:」を見て直します。

| 「理由」の表示 | 意味 | 直し方 |
|----------------|------|--------|
| version がありません | バージョンが未入力 | 「バージョン」に新しい値を入力する（→ [7章](#7-バージョンの付け方)） |
| …の座標が箕面エリアの範囲外です | 地点の座標が想定範囲外（経度 135.2〜135.8／緯度 34.6〜35.1） | 該当地点を正しい位置へドラッグ移動する、または削除する |
| id が重複しています: … | 同じ `id` の地点が複数ある | ファイル出力して `id` を確認し、重複した地点を削除して打ち直す |
| FeatureCollection／Point 形式ではありません | データ構造が不正 | 読み込んだファイルを見直す（開発担当者へ連絡） |

## 10. 付録: 公開トークンの決め方と Vercel 設定（設定担当者向け）

> この章は **設定担当者（開発担当）向け**です。日常の更新・公開を行う運用担当者は不要です。
> 作業は原則 **初回に一度だけ**（＋ローテーション時）です。

### 10.1 公開トークンの決め方

このトークン1個で公開データの全置換（偽情報の掲載・0件公開による全消去）ができるため、
**最重要の秘密**として扱います。意味のある文字列ではなく**暗号的にランダムな値**を使います。

| 条件 | 内容 |
|------|------|
| 長くランダム | 32 バイト（16進で64文字）程度。単語・日付・アプリ名は使わない |
| 埋め込まない | コードや git に入れない。Vercel の環境変数と、担当者のパスワードマネージャーだけに保存 |
| 交換できる | 漏洩が疑われたら値を更新して無効化できる（→ [10.3](#103-トークンのローテーション更新)） |

**生成コマンド（Windows PowerShell）** — `Get-Random` は暗号用途に不適なので使いません:

```powershell
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
-join ($bytes | ForEach-Object { '{0:x2}' -f $_ })
```

### 10.2 Vercel での設定

必要なのは **(A) Blob ストア接続** と **(B) 環境変数 `CLOSURES_PUBLISH_TOKEN`** の2つです。
いずれも公開先の minoh-hiking プロジェクト側の設定です。

**(A) Blob ストアをプロジェクトに接続（初回のみ）**
公開データの保存に使う `BLOB_READ_WRITE_TOKEN` が**自動で**環境変数に追加されます。

1. Vercel ダッシュボード → 対象プロジェクト → 上部タブ **Storage**
2. **Create Database**（既存があれば選択）→ **Blob** → 作成して対象プロジェクトへ **Connect**
3. Settings → Environment Variables に `BLOB_READ_WRITE_TOKEN` が入っていることを確認

**(B) 環境変数 `CLOSURES_PUBLISH_TOKEN` を設定**

1. プロジェクト → **Settings** → **Environment Variables** → **Add New**
2. **Key**: `CLOSURES_PUBLISH_TOKEN` ／ **Value**: 10.1 で生成した値 ／
   **Environment**: **Production**（「Sensitive」にできる場合はオンにする）
3. **Save**

**(C) 反映（再デプロイ）**
環境変数は**追加後の新しいデプロイから有効**です。
**Deployments → 最新デプロイの ⋯ → Redeploy** を実行し、**Ready（緑）** を待ちます。

**動作確認**

| 状態 | 挙動 |
|------|------|
| トークン未設定のまま「公開」 | `503` → 画面では **E02** |
| 間違ったトークンで「公開」 | `401` → 画面では **E01** |
| 正しいトークンで「公開」 | `200` 成功（初回のみ端末でトークン入力） |

### 10.3 トークンのローテーション（更新）

**流れ**: ① 新しい値を生成 → ② Vercel の環境変数を上書き → ③ 再デプロイ → ④ 各運用端末で再入力。

1. [10.1](#101-公開トークンの決め方) のコマンドで新しい値を作り、パスワードマネージャーに保存します。
2. **Settings → Environment Variables** で `CLOSURES_PUBLISH_TOKEN` の行の
   **右端「⋯」→ Edit**（新規の "Add New" ではありません）。**Value** を新しい値に置き換えて **Save**。
   - Sensitive 設定のため**現在の値は表示されません**（仕様）。古い値を確認する必要はなく、
     新しい値で上書きするだけで更新できます。
3. **Deployments → 最新デプロイの ⋯ → Redeploy** で反映し、**Ready** を待ちます。
4. 各運用端末では、更新後の初回「公開」時に新しいトークンの入力を求められます。
   古い値のままだと E01 になり、その端末の保存値は自動で消去されます。
   - トークンが端末に保存されるのは**公開が成功したときだけ**です。

> `BLOB_READ_WRITE_TOKEN` は公開画面で入力するものではなく、サーバーが Blob へ書き込む鍵です。
> 手動編集せず、**Storage タブ**の Blob ストア側で再発行・管理します（反映には再デプロイが必要）。

## 11. うまくいかないとき

| 症状 | 原因・対処 |
|------|------------|
| 地図をクリックしたら地点が増えてしまった | 「追加・移動」モード中です。増えた地点を選んで「削除」し、ボタンを押してモードを抜ける |
| マーカーをドラッグできない | 「追加・移動」モードに入っていません。ボタンを押してから操作する |
| 「標高の取得に失敗しました」と出る | 国土地理院の標高APIに繋がらない／データが無い位置。標高がなくても公開できます（必要なら少し動かして再取得） |
| 「現在公開中」が「取得できません」になる | 通信状況を確認し **↻** で再取得。取得できなくても公開自体は行えます |
| 「読み込みエラー: FeatureCollection 形式の geojson ではありません」 | ファイルの形式が違います。`Closure-*.geojson` か、公開APIから保存したファイルを選ぶ |
| 読み込んでも「データが見つかりませんでした」 | 統合GeoJSON（ルート・スポット等）を「登録地点」側で選んだ可能性があります。背景側で読み込む |
| ID重複でスキップされた | 同じファイルを二重に読み込んでいます。不要なら読み込み直す（一度画面を再読み込みしてやり直す） |
| バージョンが自動で入らない | 入力欄にすでに値があります（上書きしません）。手で入力し直す |
| 公開したのにユーザー側で変わらない | 端末が**まだマップを開き直していない**。開き直すと反映される。バージョンを変え忘れていないかも確認 |
| 「公開に失敗しました」（E01〜E05） | メッセージ先頭の**エラーコードで対応が決まる** → [9章](#9-公開に失敗したときの対応エラーコード別) |
