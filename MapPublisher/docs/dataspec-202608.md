# MapPublisher データ仕様書（入力 GeoJSON と公開スキーマへの整形）

**バージョン:** 2.7
**最終更新日:** 2026年8月23日
**対象アプリ:** MapPublisher
**関連:**
[機能仕様 `funcspec-202608.md`](funcspec-202608.md) /
[利用者の手引 `usersGuide-202608.md`](usersGuide-202608.md)

---

## 1. 概要

本書は **MapPublisher が読み込む GeoJSON の形式**と、
それを**公開スキーマへ整形する規則**を定義する。

### 1.1 本書の守備範囲

| 対象 | 正本 |
|------|------|
| **入力**（MapEditor / DownloadArea が出力する作業用ファイル） | **本書**（§3・§4・§5） |
| **整形規則**（入力 → 公開スキーマ） | **本書**（§7） |
| **公開スキーマ**（配信される GeoJSON・タイル一覧） | minoh-hiking `docs/publish-api-202608.md` §3 |

公開スキーマの各フィールドの定義は正本にあり、**本書には書き写さない**。
本書は「入力の何をどう落として公開スキーマにするか」を示す。

> **地図タイルのダウンロード領域（tiles）は整形しない。** 読み込んだ `tile_manifest.json` を
> そのまま公開するため、本書での守備範囲は入力の形（§5）だけで、整形規則（§7）を持たない。

### 1.2 v2.1（ClosureEditor 版）からの変更点

| 項目 | v2.1（ClosureEditor） | **v2.2 以降（MapPublisher）** | 理由 |
|------|----------------------|------------------------------|------|
| 扱うデータ | closures のみ | **ハイキングマップデータ（ポイント・ルート・スポット）を追加** | アプリ同梱の geojson を公開経由の更新に変更したため |
| トップレベル `version` | 必須で出力 | 契約 2.0 で出力しない → **契約 3.0 で必須に戻る**（画面で指定・§7.1） | 連番を意図的に飛ばす運用のため |
| 読み込みの方式 | 複数ファイルを**追加**（ID重複はスキップ） | **1ファイルで置換** | 公開が全置換であり、MapEditor は完全な1ファイルを出力するため |
| `kind` の未選択 | `unknown` を許容 | **廃止。** `closed` へ寄せて警告する | 公開スキーマの `kind` は `closed` / `difficult` のみ |
| `id` の自動採番 | 読み込み時に採番 | **行わない** | 採番は MapEditor の役割 |

### 1.3 データフロー

```
MapEditor / DownloadArea       MapPublisher                    公開API
────────────────────────      ────────────                    ───────
編集・領域指定
 ├─ MapGPS-*.geojson    ──読込→ 保持（§3）──整形（§7）──┐
 ├─ Closure-*.geojson   ──読込→ 保持（§4）──整形（§7）──┤
 └─ tile_manifest.json  ──読込→ 保持（§5）──整形しない──┤
                                                        └→ POST（公開スキーマ）

                                公開済みデータを出力（§8）◄── GET（公開中の内容）
```

**出力はデータフローの外にある。** 読み込んだ内容ではなく、公開API から取得した
公開中のデータをそのまま保存する（→ §8）。

## 2. 共通仕様

### 2.1 文字コード・形式

| 項目 | 内容 |
|------|------|
| 文字コード | UTF-8（BOM なし） |
| 形式 | GeoJSON（RFC 7946）の `FeatureCollection` |
| 拡張子 | `.geojson`（`.json` も読み込み可） |

### 2.2 座標

| 項目 | 内容 |
|------|------|
| 形式 | `[経度, 緯度]` または `[経度, 緯度, 標高]` |
| 測地系 | WGS84 |
| 数値精度 | **出力時に小数点以下5桁**へ丸める（約1m精度）。内部の保持は読み込んだ精度のまま |
| 標高の単位 | メートル |

### 2.3 トップレベル

GeoJSON のデータセット（mapdata / closures）で、読み込み時に検査するのは次の2点のみである。

| キー | 要件 |
|------|------|
| `type` | `"FeatureCollection"` であること |
| `features` | 配列であること |

`version` / `updatedAt` などトップレベルの他のキーは**読み飛ばす**。
公開時に送る `version` は**画面の入力欄**で決め、`updatedAt` はサーバーが決めるため、
入力ファイルの値はどちらも使わない。

tiles は GeoJSON ではないため、検査する項目が異なる（→ §5.2）。

## 3. 入力: ハイキングマップデータ（`MapGPS-*.geojson`）

MapEditor が出力する統合 GeoJSON。編集用の情報を含む。

### 3.1 公開対象の type

| `properties.type` | geometry | 内容 |
|---|---|---|
| `ポイントGPS` | `Point` | 緊急ポイント |
| `route` | `LineString` | ハイキングルート（中間点のみ） |
| `spot` | `Point` | スポット |

### 3.2 公開対象外の type

読み込みはするが**公開しない**。件数だけを内訳として表示する。

| `properties.type` | 表示名 | 公開しない理由 |
|---|---|---|
| `point` | 画像ポイント | 利用者アプリで描画されない（表示は `spot` のみ）。`ポイントGPS` と同じ地点の別表現であり、**除外を知らせない**（§6.2） |
| `route_waypoint` | ルート中間点 | `route` の `LineString` に含まれる |
| `area` | エリア | 利用者アプリにエリアレイヤーが無い |
| `closure` | 通行止め地点 | 別データセットとして扱う |

### 3.3 入力に現れるプロパティ

| type | プロパティ | 公開 | 備考 |
|---|---|:---:|---|
| `ポイントGPS` | `type` / `id` / `name` | ○ | `id` は現地の標識と対応する（例 `B-01`） |
| | `pointId` | × | 全件で `id` と同値 |
| | `description` | △ | **値があるときのみ**公開する（`null` は出力しない） |
| `spot` | `type` / `name` | ○ | |
| | `id` | × | どこからも参照されていない（§3.4） |
| | `source` / `description` | × | 全件が定数（`image_transformed` / `スポット（GPS変換済）`） |
| `route` | `type` / `id` | ○ | `id` は `route_{開始}_to_{終了}` 形式 |
| | `startPointGPS` / `endPointGPS` | ○ | 端点の座標。`null` のことがある |
| | `startPoint` / `endPoint` | × | ID 参照。端点座標があるため不要（§3.4） |

### 3.4 spot の `id` と route の端点参照について

- **route は spot を `name` で参照する**（`startPoint: "滝道32鉄橋"`）。
  spot の `id`（`spot02_滝道32鉄橋`）を参照している route の端点は**1件も無い**。
- 同名の spot が複数ある（「トイレ」「WC」など）が、MapEditor の出力時に
  **相手端点に近い方を選ぶ形で幾何的に解決済み**であり、その結果が
  `startPointGPS` / `endPointGPS` に入っている。
- したがって公開データでは、spot の `id` も route の `startPoint` / `endPoint` も不要である。
  利用者アプリは端点座標をそのまま使う。

> spot の `id` を出力しないため、**spot の名称が重複していても問題にならない**。
> 公開API の `id` 一意検証は `id` を持たない Feature をスキップする。

## 4. 入力: 通行止め・通行困難地点（`Closure-*.geojson`）

MapEditor が出力するファイル、または公開API から保存したファイル。

### 4.1 取り込みの判定

`properties.type` では絞り込まず、**`Point` の Feature をすべて取り込む**。
公開API から取得した geojson には `type` が無い場合があるため。

`Point` 以外（`LineString` など）は取り込まない。

### 4.2 プロパティ

| プロパティ | 型 | 必須 | 公開 | 備考 |
|---|---|:---:|:---:|---|
| `type` | `"closure"` | — | ○ | 出力時に付与する |
| `id` | string | ○ | ○ | 全地点で一意 |
| `name` | string | ○ | ○ | 地点名 |
| `kind` | `closed` / `difficult` | ○ | ○ | §4.3 |
| `reason` | string | — | △ | 値があるときのみ |
| `note` | string | — | △ | 値があるときのみ |
| `relatedRoute` | string | — | △ | 値があるときのみ |
| `updatedAt` | string | — | ○ | 地点ごとの更新日時。無ければ空文字 |
| `status` | — | — | × | **廃止済み。読み込み時に除去する** |

### 4.3 `kind` の正規化

公開スキーマの `kind` は `closed` / `difficult` のみで、**未選択は存在しない**。

| 入力の `kind` | 扱い |
|---|---|
| `closed` / `difficult` | そのまま |
| `unknown` / 空 / 未設定 / その他 | **`closed` に寄せる**。件数を数えて警告する |

警告文: `区分が未設定の{n}件を「通行止め」として扱います`

> 黙って変えると気づけないため、必ず件数を通知する。

## 5. 入力: 地図タイルのダウンロード領域（`tile_manifest.json`）

DownloadArea が出力するタイル一覧。**GeoJSON ではない**ため、
§2.3（トップレベル）と §7（整形）は適用されない。

### 5.1 構造

```json
{
  "source": "gsi-std",
  "layers": {
    "z14_default": { "z": 14, "tile_count": 8, "tiles": [[14380, 6470], ...] },
    "z15_default": { "z": 15, "tile_count": 24, "tiles": [[28760, 12940], ...] }
  }
}
```

| キー | 内容 | 公開 |
|---|---|:---:|
| `layers` | レイヤーキー → `{ z, tile_count?, tiles }` の対応 | ○ |
| `layers.*.tiles` | `[x, y]` の配列。**枚数を数える対象** | ○ |
| `source` | タイルの取得元。無ければ空文字 | ○ |
| `version` | **DownloadArea は出力しない。** 公開バージョンは画面の入力欄で決める | × |
| `updatedAt` | サーバーが決める。送っても無視される | × |

> **古いファイルには `version` が残っていることがある。** DownloadArea は以前
> 出力年月（`yyyy-MM`）を書き込んでいた。公開バージョンとは形式も意味も異なるため、
> 読み込んでも使わず、送信時に画面で指定した値で上書きする。

> **レイヤーキーは読み替えない。** `z14_default` などの命名は利用者アプリが
> 「基本／詳細」の区分に使うもので、サーバーも検証しない。件数表示にもそのまま使う。

### 5.2 取り込みの判定

読み込み時に検査するのは次の2点のみである。

| 要件 | 満たさないときのメッセージ |
|---|---|
| `layers` を持つオブジェクトであること | `タイル一覧（layers を持つ tile_manifest.json）ではありません` |
| レイヤーが1つ以上あること | `レイヤーが1つもありません` |

`z` の範囲・タイル座標の妥当性・`tile_count` と `tiles` の長さの一致は**検証しない**。
判定は公開API に任せ、失敗時は API が返した日本語メッセージをそのまま表示する。

### 5.3 件数の数え方

**Feature 数ではなくタイルの枚数**を数える（契約 §5.2）。

| 表示 | 内容 |
|---|---|
| レイヤー別 | `layers` の各キーについて `tiles` の要素数。マニフェストに現れる順で並べる |
| 合計 | 全レイヤーの枚数の合計 |

`tiles` が配列でないレイヤーは 0 枚として数える（不正な中身の判定はサーバーの責務）。

## 6. 読み込み処理仕様

### 6.1 置換方式

**読み込むと、そのデータセットの内容はファイルの内容で置き換わる。**
複数ファイルの同時選択・追加読み込みは行わない。

理由: 公開が全置換であり、MapEditor は完全な1ファイルを出力する。
読み込みも置換に揃えることで、同じファイルを2回読んで件数が倍になる事故を防ぎ、
ID による重複検出も不要になる。

### 6.2 エラー・警告

| 状況 | メッセージ | 種別 |
|---|---|---|
| JSON として読めない | `読み込みエラー ({ファイル名}): JSONとして読み込めません` | error |
| FeatureCollection でない | `読み込みエラー ({ファイル名}): FeatureCollection 形式の geojson ではありません` | error |
| タイル一覧でない | `読み込みエラー ({ファイル名}): タイル一覧（layers を持つ tile_manifest.json）ではありません` | error |
| ハイキングマップデータが0件 | `{ファイル名}: 公開対象のデータが見つかりませんでした` | warning |
| 通行止めが0件 | `{ファイル名}: 通行止め・通行困難地点が見つかりませんでした` | warning |
| タイルが0枚 | `{ファイル名}: タイルが1枚もありません` | warning |
| タイルを読み込んだ | `{n}枚を読み込みました（z14_default 8 / z15_default 24 / …）` | success |
| 公開対象外を含む | `{n}件を読み込みました（…）` ＋ `公開対象外 {内訳} は公開しません` | success |
| 公開対象外が `point` のみ | `{n}件を読み込みました（…）` のみ。**除外は知らせない** | success |
| `kind` を寄せた | `{n}件を読み込みました（…）` ＋ `区分が未設定の{k}件を「通行止め」として扱います` | warning |

> **`point` の除外は知らせない。** `ポイントGPS` と同じ地点を別に持っているだけで、
> 除外は仕様どおり・運用者の対応も不要なため、毎回知らせても判断材料にならない。
> 知らせるべき除外（エリアや通行止め地点の混入）が埋もれることを避ける。
> 対象は `js/constants.js` の `SILENT_EXCLUDED_TYPES` で定義する。

## 7. 公開スキーマへの整形

読み込んだ内容から、公開スキーマ（正本: `publish-api-202608.md` §3）を組み立てる。

**対象は mapdata と closures のみ。** tiles は整形せず、読み込んだ内容をそのまま送る。

### 7.1 トップレベル

```json
{ "version": "2026.03", "type": "FeatureCollection", "features": [ ... ] }
```

**`version` を含める**（契約 3.0）。値は画面の「公開バージョン」入力欄で決まり、
形式は `yyyy.nn`（2桁ゼロ埋め）。判定は `js/version.js` に置く。

**`updatedAt` は含めない。** サーバーが公開時刻を付ける。

> `version` はデータの中身ではなく公開の操作で決まるため、各データモジュールの
> `buildPublishData()` ではなく `js/publish.js` が送信直前に足す。
> tiles も同じで、読み込んだ `tile_manifest.json` に `version` だけを重ねて送る。

### 7.2 プロパティの対応

| type | 出力するプロパティ（この順） |
|---|---|
| `ポイントGPS` | `type` → `id` → `name` →（`description`） |
| `spot` | `type` → `name` |
| `route` | `type` → `id` → `startPointGPS` → `endPointGPS` |
| `closure` | `type` → `id` → `name` → `kind` →（`reason`）→（`note`）→（`relatedRoute`）→ `updatedAt` |

括弧付きは**値があるときのみ**出力する。

### 7.3 座標

geometry の座標、および `startPointGPS` / `endPointGPS` を
**小数点以下5桁**に丸める（§2.2）。

### 7.4 出力例

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "properties": { "type": "ポイントGPS", "id": "B-01", "name": "聖天展望台" },
      "geometry": { "type": "Point", "coordinates": [135.47258, 34.839, 184.6] }
    },
    {
      "type": "Feature",
      "properties": { "type": "spot", "name": "滝道32鉄橋" },
      "geometry": { "type": "Point", "coordinates": [135.47102, 34.84955, 162.3] }
    },
    {
      "type": "Feature",
      "properties": {
        "type": "route",
        "id": "route_H-04_to_H-11",
        "startPointGPS": [135.4713, 34.87451, 534],
        "endPointGPS": [135.47341, 34.86829, 552.9]
      },
      "geometry": {
        "type": "LineString",
        "coordinates": [[135.47142, 34.87301], [135.47205, 34.87088]]
      }
    },
    {
      "type": "Feature",
      "properties": {
        "type": "closure", "id": "C-01", "name": "落石地点",
        "kind": "closed", "reason": "落石", "updatedAt": "2026-08-10"
      },
      "geometry": { "type": "Point", "coordinates": [135.47261, 34.8391, 184.62] }
    }
  ]
}
```

## 8. 公開済みデータの出力

**いま公開されているデータ**を保存する。読み込んだファイルの写しでも、整形結果でもない。

| 項目 | 内容 |
|------|------|
| 取得元 | 各データセットの `GET`（`/api/mapdata` / `/api/closures` / `/api/tiles`） |
| 出力内容 | **サーバーの応答をそのまま**。整形しない |
| トップレベル | サーバーが返したまま。`version` と `updatedAt` を**含む** |
| 読み込みの要否 | 不要（ファイルを読み込んでいなくても出力できる） |
| 保存方法 | File System Access API（未対応ブラウザではダウンロード） |
| 取得できないとき | 出力せず警告を表示 |
| 未公開のとき | 出力せず警告を表示 |

公開前に出力すれば前回公開分、公開後に出力すれば今回公開分が得られる。

> **整形しない理由。** 公開スキーマの正本はサーバー（`publish-api-202608.md` §3）にある。
> 取得した内容をクライアントで組み直すと、整形規則を二重に持つことになる。

### 8.1 ファイル名

| データセット | 形式 | 例 |
|---|---|---|
| ハイキングマップデータ | `MapData-{version}_P{ポイント}_R{ルート}_S{スポット}.geojson` | `MapData-2026.03_P174_R263_S189.geojson` |
| 通行止め | `Closure-{version}_C{通行止め}_D{通行困難}.geojson` | `Closure-2026.06_C5_D2.geojson` |
| 地図タイル | `TileManifest-{version}_L{レイヤー数}_T{タイル枚数}.json` | `TileManifest-2026.01_L5_T1248.json` |

**日付ではなくバージョンで識別する。** 出力するのは公開済みデータであり、
同じ日に別のバージョンを取り出しても名前がぶつからないようにするため。
バージョンが取れないときのみ `yyyymmdd` で代用する。

タイルのレイヤー別枚数は5つあり名前に入れると長すぎるため、レイヤー数と合計だけを付ける。

### 8.2 出力ファイルの使い道

| 用途 | 可否 |
|---|---|
| 公開されている内容の確認・控え | ○ |
| MapPublisher に読み込み直す（公開のやり直し） | ○ 読み込める。ただし `version` はサーバーが新たに採番する |
| **MapEditor に戻して編集する** | **×** 編集用の識別子（`spot` の `id`、route の `startPoint` / `endPoint`）が落ちている。編集は MapEditor 側の元ファイルで行う |
