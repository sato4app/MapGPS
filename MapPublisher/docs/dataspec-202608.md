**バージョン:** 2.4
**最終更新日:** 2026年8月18日
**対象アプリ:** MapPublisher
**関連:**
[機能仕様 `funcspec-202608.md`](funcspec-202608.md) /
[利用者の手引 `usersGuide-202608.md`](usersGuide-202608.md)

## 1. 概要

本書は **MapPublisher が読み込む GeoJSON の形式**と、
それを**公開スキーマへ整形する規則**を定義する。

### 1.1 本書の守備範囲

| 対象 | 正本 |
|------|------|
| **入力**（MapEditor が出力する作業用 GeoJSON） | **本書**（§3・§4） |
| **整形規則**（入力 → 公開スキーマ） | **本書**（§6） |
| **公開スキーマ**（配信される GeoJSON） | minoh-hiking `docs/publish-api-202608.md` §3 |

公開スキーマの各フィールドの定義は正本にあり、**本書には書き写さない**。
本書は「入力の何をどう落として公開スキーマにするか」を示す。

### 1.2 v2.1（ClosureEditor 版）からの変更点

| 項目 | v2.1（ClosureEditor） | **v2.2 以降（MapPublisher）** | 理由 |
|------|----------------------|------------------------------|------|
| 扱うデータ | closures のみ | **ハイキングマップデータ（ポイント・ルート・スポット）を追加** | アプリ同梱の geojson を公開経由の更新に変更したため |
| トップレベル `version` | 必須で出力 | **出力しない** | サーバー採番に変更（契約 2.0） |
| 読み込みの方式 | 複数ファイルを**追加**（ID重複はスキップ） | **1ファイルで置換** | 公開が全置換であり、MapEditor は完全な1ファイルを出力するため |
| `kind` の未選択 | `unknown` を許容 | **廃止。** `closed` へ寄せて警告する | 公開スキーマの `kind` は `closed` / `difficult` のみ |
| `id` の自動採番 | 読み込み時に採番 | **行わない** | 採番は MapEditor の役割 |
| 出力内容 | 読み込んだ内容をそのまま | **公開スキーマへ整形した結果** | 公開する内容そのものを確認できるようにするため |

### 1.3 データフロー

```
MapEditor                    MapPublisher                     公開API
─────────                   ────────────                     ───────
編集
 ├─ MapGPS-*.geojson  ──読込→ 保持（§3）──整形（§6）──┐
 └─ Closure-*.geojson ──読込→ 保持（§4）──整形（§6）──┤
                                    │                 └→ POST（公開スキーマ）
                                    └→ 整形結果をファイル出力（§7）
```

## 2. 共通仕様

### 2.1 文字コード・形式

| 項目 | 内容 |
|------|------|
| 文字コード | UTF-8（BOM なし） |
| 形式 | GeoJSON（RFC 7946）の `FeatureCollection` |
| 拡張子 | `.geojson`（`.json` も読み込み可） |

### 2.2 座標

| 項目 | 内容 |
|------|------|
| 形式 | `[経度, 緯度]` または `[経度, 緯度, 標高]` |
| 測地系 | WGS84 |
| 数値精度 | **出力時に小数点以下5桁**へ丸める（約1m精度）。内部の保持は読み込んだ精度のまま |
| 標高の単位 | メートル |

### 2.3 トップレベル

読み込み時に検査するのは次の2点のみである。

| キー | 要件 |
|------|------|
| `type` | `"FeatureCollection"` であること |
| `features` | 配列であること |

`version` / `updatedAt` などトップレベルの他のキーは**読み飛ばす**。
公開時に送る値はサーバーが決めるため、入力ファイルの値は使わない。

## 3. 入力: ハイキングマップデータ（`MapGPS-*.geojson`）

MapEditor が出力する統合 GeoJSON。編集用の情報を含む。

### 3.1 公開対象の type

| `properties.type` | geometry | 内容 |
|---|---|---|
| `ポイントGPS` | `Point` | 緊急ポイント |
| `route` | `LineString` | ハイキングルート（中間点のみ） |
| `spot` | `Point` | スポット |

### 3.2 公開対象外の type

読み込みはするが**公開しない**。件数だけを内訳として表示する。

| `properties.type` | 表示名 | 公開しない理由 |
|---|---|---|
| `point` | 画像ポイント | 利用者アプリで描画されない（表示は `spot` のみ）。`ポイントGPS` と同じ地点の別表現であり、**除外を知らせない**（§5.2） |
| `route_waypoint` | ルート中間点 | `route` の `LineString` に含まれる |
| `area` | エリア | 利用者アプリにエリアレイヤーが無い |
| `closure` | 通行止め地点 | 別データセットとして扱う |

### 3.3 入力に現れるプロパティ

| type | プロパティ | 公開 | 備考 |
|---|---|:---:|---|
| `ポイントGPS` | `type` / `id` / `name` | ○ | `id` は現地の標識と対応する（例 `B-01`） |
| | `pointId` | × | 全件で `id` と同値 |
| | `description` | △ | **値があるときのみ**公開する（`null` は出力しない） |
| `spot` | `type` / `name` | ○ | |
| | `id` | × | どこからも参照されていない（§3.4） |
| | `source` / `description` | × | 全件が定数（`image_transformed` / `スポット（GPS変換済）`） |
| `route` | `type` / `id` | ○ | `id` は `route_{開始}_to_{終了}` 形式 |
| | `startPointGPS` / `endPointGPS` | ○ | 端点の座標。`null` のことがある |
| | `startPoint` / `endPoint` | × | ID 参照。端点座標があるため不要（§3.4） |

### 3.4 spot の `id` と route の端点参照について

- **route は spot を `name` で参照する**（`startPoint: "滝道32鉄橋"`）。
  spot の `id`（`spot02_滝道32鉄橋`）を参照している route の端点は**1件も無い**。
- 同名の spot が複数ある（「トイレ」「WC」など）が、MapEditor の出力時に
  **相手端点に近い方を選ぶ形で幾何的に解決済み**であり、その結果が
  `startPointGPS` / `endPointGPS` に入っている。
- したがって公開データでは、spot の `id` も route の `startPoint` / `endPoint` も不要である。
  利用者アプリは端点座標をそのまま使う。

> spot の `id` を出力しないため、**spot の名称が重複していても問題にならない**。
> 公開API の `id` 一意検証は `id` を持たない Feature をスキップする。

## 4. 入力: 通行止め・通行困難地点（`Closure-*.geojson`）

MapEditor が出力するファイル、または公開API から保存したファイル。

### 4.1 取り込みの判定

`properties.type` では絞り込まず、**`Point` の Feature をすべて取り込む**。
公開API から取得した geojson には `type` が無い場合があるため。

`Point` 以外（`LineString` など）は取り込まない。

### 4.2 プロパティ

| プロパティ | 型 | 必須 | 公開 | 備考 |
|---|---|:---:|:---:|---|
| `type` | `"closure"` | — | ○ | 出力時に付与する |
| `id` | string | ○ | ○ | 全地点で一意 |
| `name` | string | ○ | ○ | 地点名 |
| `kind` | `closed` / `difficult` | ○ | ○ | §4.3 |
| `reason` | string | — | △ | 値があるときのみ |
| `note` | string | — | △ | 値があるときのみ |
| `relatedRoute` | string | — | △ | 値があるときのみ |
| `updatedAt` | string | — | ○ | 地点ごとの更新日時。無ければ空文字 |
| `status` | — | — | × | **廃止済み。読み込み時に除去する** |

### 4.3 `kind` の正規化

公開スキーマの `kind` は `closed` / `difficult` のみで、**未選択は存在しない**。

| 入力の `kind` | 扱い |
|---|---|
| `closed` / `difficult` | そのまま |
| `unknown` / 空 / 未設定 / その他 | **`closed` に寄せる**。件数を数えて警告する |

警告文: `区分が未設定の{n}件を「通行止め」として扱います`

> 黙って変えると気づけないため、必ず件数を通知する。

## 5. 読み込み処理仕様

### 5.1 置換方式

**読み込むと、そのデータセットの内容はファイルの内容で置き換わる。**
複数ファイルの同時選択・追加読み込みは行わない。

理由: 公開が全置換であり、MapEditor は完全な1ファイルを出力する。
読み込みも置換に揃えることで、同じファイルを2回読んで件数が倍になる事故を防ぎ、
ID による重複検出も不要になる。

### 5.2 エラー・警告

| 状況 | メッセージ | 種別 |
|---|---|---|
| JSON として読めない | `読み込みエラー ({ファイル名}): JSONとして読み込めません` | error |
| FeatureCollection でない | `読み込みエラー ({ファイル名}): FeatureCollection 形式の geojson ではありません` | error |
| ハイキングマップデータが0件 | `{ファイル名}: 公開対象のデータが見つかりませんでした` | warning |
| 通行止めが0件 | `{ファイル名}: 通行止め・通行困難地点が見つかりませんでした` | warning |
| 公開対象外を含む | `{n}件を読み込みました（…）` ＋ `公開対象外 {内訳} は公開しません` | success |
| 公開対象外が `point` のみ | `{n}件を読み込みました（…）` のみ。**除外は知らせない** | success |
| `kind` を寄せた | `{n}件を読み込みました（…）` ＋ `区分が未設定の{k}件を「通行止め」として扱います` | warning |

> **`point` の除外は知らせない。** `ポイントGPS` と同じ地点を別に持っているだけで、
> 除外は仕様どおり・運用者の対応も不要なため、毎回知らせても判断材料にならない。
> 知らせるべき除外（エリアや通行止め地点の混入）が埋もれることを避ける。
> 対象は `js/constants.js` の `SILENT_EXCLUDED_TYPES` で定義する。

## 6. 公開スキーマへの整形

読み込んだ内容から、公開スキーマ（正本: `publish-api-202608.md` §3）を組み立てる。

### 6.1 トップレベル

```json
{ "type": "FeatureCollection", "features": [ ... ] }
```

**`version` と `updatedAt` は含めない。** サーバーが決めるため（契約 2.0）。

### 6.2 プロパティの対応

| type | 出力するプロパティ（この順） |
|---|---|
| `ポイントGPS` | `type` → `id` → `name` →（`description`） |
| `spot` | `type` → `name` |
| `route` | `type` → `id` → `startPointGPS` → `endPointGPS` |
| `closure` | `type` → `id` → `name` → `kind` →（`reason`）→（`note`）→（`relatedRoute`）→ `updatedAt` |

括弧付きは**値があるときのみ**出力する。

### 6.3 座標

geometry の座標、および `startPointGPS` / `endPointGPS` を
**小数点以下5桁**に丸める（§2.2）。

### 6.4 出力例

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "properties": { "type": "ポイントGPS", "id": "B-01", "name": "聖天展望台" },
      "geometry": { "type": "Point", "coordinates": [135.47258, 34.839, 184.6] }
    },
    {
      "type": "Feature",
      "properties": { "type": "spot", "name": "滝道32鉄橋" },
      "geometry": { "type": "Point", "coordinates": [135.47102, 34.84955, 162.3] }
    },
    {
      "type": "Feature",
      "properties": {
        "type": "route",
        "id": "route_H-04_to_H-11",
        "startPointGPS": [135.4713, 34.87451, 534],
        "endPointGPS": [135.47341, 34.86829, 552.9]
      },
      "geometry": {
        "type": "LineString",
        "coordinates": [[135.47142, 34.87301], [135.47205, 34.87088]]
      }
    },
    {
      "type": "Feature",
      "properties": {
        "type": "closure", "id": "C-01", "name": "落石地点",
        "kind": "closed", "reason": "落石", "updatedAt": "2026-08-10"
      },
      "geometry": { "type": "Point", "coordinates": [135.47261, 34.8391, 184.62] }
    }
  ]
}
```

## 7. 出力処理仕様（整形結果のファイル出力）

公開前の内容確認と、公開に失敗したときの控えの2つの用途を持つ。

| 項目 | 内容 |
|------|------|
| 出力内容 | §6 で整形した結果 |
| トップレベル | `type` / `updatedAt`（出力日時・ISO 8601 オフセット付き）/ `features` |
| 保存方法 | File System Access API（未対応ブラウザではダウンロード） |
| 0件のとき | 出力せず警告を表示 |

### 7.1 ファイル名

| データセット | 形式 | 例 |
|---|---|---|
| ハイキングマップデータ | `MapData-yyyymmdd_P{ポイント}_R{ルート}_S{スポット}.geojson` | `MapData-20260818_P167_R292_S209.geojson` |
| 通行止め | `Closure-yyyymmdd_C{通行止め}_D{通行困難}.geojson` | `Closure-20260818_C8_D4.geojson` |

> 出力ファイルには `version` が無いため、**公開のやり直しに使っても
> 巻き戻しにはならない**（version はサーバーが新たに採番する）。
> ただし内容は出力時点のものなので、件数差分の確認は必ず行うこと。
