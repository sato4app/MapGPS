# MapPublisher 利用者の手引（ハイキングマップデータの公開）

**バージョン:** 1.8
**最終更新日:** 2026年8月25日
**対象:** 運用担当者（ハイキングマップデータ・通行止め情報・地図タイルを公開する人）
**関連:**
[機能仕様 `funcspec-202608.md`](funcspec-202608.md) /
[データ仕様 `dataspec-202608.md`](dataspec-202608.md)

---

## 1. この手引について

ハイキングマップアプリ（minoh-hiking）に表示するデータを**公開**する手順を説明します。

公開できるのは次の3つです。

画面に並ぶ順（更新頻度の高い順）に示します。

| データ | 内容 | 作るアプリ | 更新のめやす | 手順 |
|---|---|---|---|---|
| **通行止め・通行困難地点** | 通行止め・通行困難の地点 | MapEditor | 随時 | [5章](#5-手順通行止め通行困難地点の公開) |
| **ハイキングマップデータ** | 緊急ポイント・ハイキングルート・スポット | MapEditor | 年に数回 | [6章](#6-手順ハイキングマップデータの公開) |
| **地図タイルのダウンロード領域** | オフライン地図に入れるタイルの一覧 | DownloadArea | まれ | [7章](#7-手順地図タイルのダウンロード領域の公開) |

> **このアプリでは編集できません。**
> 地点の追加・移動・名称の変更などは **MapEditor** で、
> タイルの範囲指定は **DownloadArea** で行い、
> そこで出力したファイルをこのアプリで読み込んで公開します。

---

## 2. 事前準備

| 準備するもの | 内容 |
|---|---|
| 公開するファイル | MapEditor で出力した `MapGPS-*.geojson` / `Closure-*.geojson`、または DownloadArea で出力した `tile_manifest.json` |
| 公開トークン | 初回の公開時に一度だけ入力します（→ [9章](#9-公開トークンについて)）。**3つのデータで共通**です |
| 通信環境 | 公開はインターネット接続が必要です |

対応端末は **PC のみ**です。スマートフォンでの利用は想定していません。

---

## 3. 画面の見方

画面の右上にパネルがあり、**3つのセクション**が縦に並んでいます。
更新頻度の高いものが上です。

**開いたとき**（起動直後はどれも閉じています）

```
▶ 通行止め・通行困難地点
    現在公開中 [ 2026.05（7件） ]
▼ ハイキングマップデータ                  ← 見出しをクリックして開いた
    現在公開中 [ 2026.02（626件） ]
  ┌────────────────────────────────┐
  │ ファイル読み込み / 消去        │
  │ 地図に表示 / 件数              │
  │ 公開バージョン [ 2026.03 ]     │
  │ 公開 / 公開済みデータを出力    │
  └────────────────────────────────┘
▶ 地図タイルのダウンロード領域
    現在公開中 [ 取得できません ]
```

### 3.1 セクションの開き方

**起動したときは、どれも開いていません。** 3つの「現在公開中」だけが並びます。
まず、いま何が公開されているかを見渡してください。

**作業するデータの見出しをクリックすると開きます。** 1つ開くと、ほかは自動的に閉じます。

> **閉じていても「現在公開中」は見えます。** 3つのバージョンを一目で確認できるように、
> 見出しに置いてあります。閉じてもデータが消えるわけではありません。

### 3.2 各部分の意味

| 部分 | 場所 | 内容 |
|---|---|---|
| 現在公開中 | 見出し | いまユーザーに見えているバージョンと件数です |
| ファイル読み込み | 本体 | 公開するファイルを選びます |
| 地図に表示 | 本体 | 読み込んだデータの表示・非表示を切り替えます |
| ズームレベル | 本体 | **地図タイルだけ**にあります。地図に描くタイルの範囲をズームレベルで選びます（→ [7章](#7-手順地図タイルのダウンロード領域の公開)） |
| 件数 | 本体 | 種別ごとの件数と合計です。**公開する内容そのもの**を示します |
| 消去 | 本体 | 読み込んだデータを取り消します |
| 公開バージョン | 本体 | これから公開する版の番号です。**自動で次の番号が入ります**（→ [8章](#8-バージョンについて)） |
| 公開 | 本体 | 確認画面を経て、ユーザーに公開します |
| 公開済みデータを出力 | 本体 | **いま公開されているデータ**をファイルに保存します |
| ↻（パネル下部） | — | 3つ分の「現在公開中」を取得し直します |
| トークン消去 | — | この端末に保存した公開トークンを消します |

> **「公開済みデータを出力」は、読み込んだファイルではなく公開中の内容を保存します。**
> 公開する前に押せば前回公開した分、公開したあとに押せば今回公開した分が得られます。
> ファイルを読み込んでいなくても押せます。

> **「地図に表示」を切り替えても、開いているセクションとは連動しません。**
> 通行止め地点をハイキングマップデータに重ねたまま、別のセクションを開けます。

## 4. 更新の全体フロー

```
MapEditor で編集 / DownloadArea で領域指定
      │
      ├─ ファイル出力
      ▼
MapPublisher でセクションを開いて読み込む
      │
      ├─ 地図と件数で内容を確認
      ▼
「公開」→ 確認画面で件数差分をチェック
      │
      ▼
minoh-hiking で表示を確認
```

**バージョンは自動で入ります。** 「現在公開中」の次の番号が「公開バージョン」欄に入るので、
通常はそのまま公開できます（→ [8章](#8-バージョンについて)）。

**公開に失敗したときは、画面が公開中の状態に戻ります**
（→ [10章](#10-公開に失敗したときの対応エラーコード別)）。

## 5. 手順（通行止め・通行困難地点の公開）

いちばん頻度の高い作業です。

### 手順1. セクションを開いてファイルを読み込む

**「通行止め・通行困難地点」の見出しをクリック**して開き、
**「ファイル読み込み」** から MapEditor で出力した `Closure-*.geojson` を選びます。

- 地図に地点が表示され、件数が `通行止め n / 通行困難 m（計 N件）` と出ます。
- **読み込むと前の内容は置き換わります**（追加ではありません）。
- `区分が未設定の{n}件を「通行止め」として扱います` と出たら、MapEditor 側で
  区分が設定されていない地点があります。そのままでも公開できますが、
  意図と違う場合は MapEditor で直してから出力し直してください。

### 手順2. 内容を確認する

- 地図上のマーカーをクリックすると、名称・区分・理由・備考・更新日が表示されます。
  **ユーザーに見える内容と同じ**です。
- 件数が想定どおりか確認します。

### 手順3.「公開バージョン」を確認して「公開」を押す

**通常はそのままで構いません。** 「現在公開中」の次の番号が入っています。
番号を飛ばしたいときだけ書き換えます（→ [8章](#8-バージョンについて)）。

「公開」を押すと確認画面が出ます。**バージョンと件数を必ず見てください。**

```
通行止め・通行困難地点をユーザーへ公開します。

現在公開中: 2026.05
  通行止め 8 / 通行困難 4（計 12件）

これから公開: 2026.06
  通行止め 9 / 通行困難 4（計 13件）

よろしいですか？
```

- 件数が**減る**場合は、`【注意】件数が減ります:` と種別ごとに表示されます。
  古いファイルを読み込んでいないか確認してください。
- **0件のとき**は `【注意】0件のため、公開中のデータがすべて地図から消えます。` と出ます。
  全解除の意図がなければ **キャンセル** してください。

初回は公開トークンの入力を求められます（→ [9章](#9-公開トークンについて)）。

### 手順4. 結果を確認する

成功すると、公開したバージョンと件数が表示されます。

```
通行止め・通行困難地点 バージョン 2026.06（13件）をユーザーへ公開しました。
```

「公開バージョン」欄には、次の番号（`2026.07`）が自動で入ります。

minoh-hiking を開き直して、地図に反映されていることを確認してください。

## 6. 手順（ハイキングマップデータの公開）

ルート・スポット・緊急ポイントを更新したときの手順です。頻度は多くありません。

### 手順1. セクションを開いてファイルを読み込む

**「ハイキングマップデータ」の見出しをクリック**して開き、
**「ファイル読み込み」** から MapEditor で出力した `MapGPS-*.geojson` を選びます。

- 件数が `ポイント n / ルート m / スポット k（計 N件）` と出ます。
- `公開対象外 エリア 3 は公開しません` のような表示が出ることがあります。
  **これは正常です。** 利用者アプリで使わない種別は公開しません。
  心当たりのない種別が出たときは、読み込むファイルを間違えていないか確認してください。

### 手順2. 地図で確認する

- ルート線が**端のスポットまで繋がっているか**を確認します。
  この画面はユーザーに見えるのと同じ描き方をしています。
- スポットや緊急ポイントの位置・名称をクリックして確認します。

### 手順3.「公開バージョン」を確認して「公開」を押す

確認画面で**バージョンと種別ごとの件数**を確認します。ハイキングマップデータの公開は、
誤ると**ハイキングマップ全体が消えます**。件数が大きく減っていないか必ず見てください。

### 手順4. 結果を確認する

minoh-hiking を開き直して、ルート・スポットが正しく表示されることを確認します。

## 7. 手順（地図タイルのダウンロード領域の公開）

オフライン地図に入れるタイルの範囲を変えたときの手順です。頻度はごくまれです。

> **このデータも地図に表示されます。** ダウンロードする範囲が紫の枠で描かれます。
> 範囲はズームレベルごとに違うため、**一度に描かれるのは1レベル分**です。
> **レイヤーごとの枚数**と併せて確認してください。

### 手順1. セクションを開いてファイルを読み込む

**「地図タイルのダウンロード領域」の見出しをクリック**して開き、
**「ファイル読み込み」** から DownloadArea で出力した `tile_manifest.json` を選びます。

- 件数が `z14_default 8 / z15_default 24 / z16_default 87 …（計 N枚）` と出ます。
- **レイヤーが1つ欠けていないか**を必ず確認してください。合計だけを見ていると、
  範囲の違うファイルや壊れたファイルとの取り違えに気づけません。

### 手順2. 地図で範囲を確認する

読み込むと、**「地図に表示」** が入った状態で範囲が紫の枠で描かれます。

- 右の **「ズームレベル」** で描くレベルを選びます。**最初は z17** が選ばれています。
  ファイルに z17 が無いときは、いちばん近いレベルが選ばれます。
- ハイキングマップのルートやスポットが**枠の中に収まっているか**を確認してください。
  枠からはみ出した場所は、オフラインでは地図が表示されません。
- ズームレベルを切り替えて、**レベルごとに範囲が違わないか**を見ます。
  詳しいレベル（z18 など）だけ範囲が狭いのは、通常どおりです。

> **枠の縁が階段状になります。** 地図タイルは四角い升目で、範囲は升目の単位で決まります。
> 縁のギザギザはその升目の大きさで、異常ではありません。

> **通行止め地点やハイキングマップと重ねて見られます。** それぞれのセクションの
> 「地図に表示」を入れたままにしておけば、同時に表示されます。

### 手順3.「公開バージョン」を確認して「公開」を押す

確認画面にバージョンとレイヤー別の枚数が並びます。枚数が**減る**場合は
`【注意】件数が減ります:` とレイヤーごとに表示されます。
ダウンロード範囲を狭めた覚えがなければ **キャンセル** してください。

### 手順4. 結果を確認する

成功すると、採番されたバージョンと枚数が表示されます。

```
地図タイルのダウンロード領域 バージョン 2026.01（1248枚）をユーザーへ公開しました。
```

> **2026年8月23日時点で、このデータの公開先はまだ準備できていません。**
> 「現在公開中」は `取得できません` と表示され、公開しようとすると
> **E06（公開先が見つかりません）** になります。
> サーバー側の準備が済むまでお待ちください（→ [10章](#10-公開に失敗したときの対応エラーコード別)）。

## 8. バージョンについて

**通常は入力しません。** 「公開バージョン」欄には、次の番号が自動で入ります。

### 8.1 形式

**3つとも `年.連番` です。連番は2桁**（`01`〜`99`）で、1桁のときは `0` を付けます。

| 例 | 意味 |
|---|---|
| `2026.01` | 2026年の1回目 |
| `2026.10` | 2026年の10回目 |
| `2027.01` | 年が変わって1回目 |

年が変わると、連番は `01` に戻ります。

### 8.2 自動で入る番号

「現在公開中」を取得したときに、**その次の番号**が入ります。

| 現在公開中 | 自動で入る番号 |
|---|---|
| `2026.05` | `2026.06` |
| `2026.09` | `2026.10` |
| 前の年（`2025.12`） | `2026.01` |
| 未公開・取得できない | `2026.01`（または空欄） |

### 8.3 手で書き換えられます

**番号を意図的に飛ばしたいときは、欄を直接書き換えてください。**
`2026.08` の次を `2026.10` にする、といった使い方ができます。

- 一度書き換えると、**↻ を押しても元に戻りません**（入力した番号が守られます）。
- **公開に成功すると、次の番号が改めて入ります。**

### 8.4 公開できない番号

| 入力 | 画面の表示 |
|---|---|
| `2026.1`（1桁）・`26.01`・`abc` など形式違い | `公開バージョンは yyyy.nn 形式で入力してください（例: 2026.01）` |
| **現在公開中と同じ番号** | `バージョン {番号} はすでに公開されています。番号を進めてください` |

> **同じ番号では公開できません。** バージョンが変わらないと、
> **ユーザーの端末はデータを取得し直しません。** 公開したつもりでも届かないため、
> アプリとサーバーの両方で止めています。

前の番号（`2026.06` → `2026.04`）での公開は**できます**。意図的な差し戻しのためです。

- **バージョンが変わると、ユーザーの端末は次回の起動時にデータを取得し直します。**

> **バージョンでは「古いファイルからの公開」を見分けられません。**
> 古い内容にも新しい番号を付けられるためです。
> 確認画面の**件数差分**が唯一の手がかりなので、必ず確認してください。

## 9. 公開トークンについて

- 公開トークンは、公開先サーバー（Vercel）の環境変数 `MAP_PUBLISH_TOKEN` と**同じ値**です。
- **3つのデータで共通**です。
- **初回の「公開」時に一度入力**すると、**その端末**に保存され、以降は再入力不要です。
- **アプリのコードには埋め込まれていません**（運用担当者だけが知っている前提）。
- トークンが違うと **「【E01】公開トークンが正しくありません」** と表示され、保存が消えます。
  このとき読み込んだデータも公開中の状態に戻るため、
  **ファイルを読み込み直してから**もう一度「公開」を押し、正しい値を入力してください。
- 別の端末で公開するときは、その端末で改めて入力が必要です。
- **共用の端末を離れるときは「トークン消去」ボタン**で保存済みトークンを消してください。

## 10. 公開に失敗したときの対応（エラーコード別）

「公開」に失敗すると、**エラーコード（E01〜E06）付きのメッセージ**が出ます。
運用担当者は、**表示されたコードと文面をそのまま開発担当者に伝えれば**原因を切り分けられます。
まず自分で試せることを行い、直らなければ開発担当者へ連絡してください。

### 10.0 失敗すると画面は公開中の状態に戻ります

**読み込んだデータは破棄され、いま公開されているデータが読み直されます。**
`公開中の{データ名}に戻しました` と表示されます。

公開されていない内容が地図や件数に残っていると、
いま何が公開されているのか分からなくなるためです。

**やり直すときは、ファイルの読み込みからです。** 元のファイルは端末に残っているので、
「ファイル読み込み」で選び直してください。

> **通信エラー（E05）のときだけは戻りません。** 公開中のデータも取得できないためです。
> `公開中の{データ名}を取得できませんでした。画面には読み込んだデータが残っています`
> と表示されます。このときの画面は、**公開されている内容とは違う**ことに注意してください。

### 10.1 コード早見表

| コード | 画面の要点 | 主な原因 | まず試すこと | 開発担当者の対応（サーバー側） |
|--------|-----------|----------|--------------|----------------------------|
| **E01** | 公開トークンが正しくありません | 入力したトークンが違う | ファイルを読み込み直し、もう一度「公開」→ 正しいトークンを入力（→ [9章](#9-公開トークンについて)） | 正しい `MAP_PUBLISH_TOKEN` を伝える／必要ならローテーション（→ [11.3](#113-トークンのローテーション更新)） |
| **E02** | 公開機能が設定されていません | サーバーに公開トークンが未設定、または設定後に未反映 | （操作では直らない）開発担当者へ連絡 | `MAP_PUBLISH_TOKEN` を設定し**再デプロイ**（→ [11.2](#112-vercel-での設定)） |
| **E03** | 公開データに不備があります | 送信データの中身が不正、またはバージョンの形式違い・重複 | 表示の「理由」を見て直し、出力し直したファイルを読み込んで再公開（→ 下記 10.2） | 通常は不要（データ側の問題） |
| **E04** | 公開データの保存に失敗しました | 公開ストア（Blob）への保存失敗 | 少し時間をおき、ファイルを読み込み直して再試行 | Blob 接続と `BLOB_READ_WRITE_TOKEN` を確認して**再デプロイ**、Runtime Logs で生エラー確認 |
| **E05** | サーバーに接続できません（通信エラー） | 通信断・接続不良・サーバー障害 | 通信状況を確認して再試行 | Vercel の稼働・エンドポイントの到達性を確認 |
| **E06** | 公開先が見つかりません | エンドポイントが未実装・未デプロイ | （操作では直らない）開発担当者へ連絡 | `/api/mapdata` `/api/closures` `/api/tiles` `/api/manifest` の実装・デプロイ状況を確認 |

> **地図タイルの公開は、現在いつ試しても E06 になります。**
> 公開先（`/api/tiles`）がまだ用意されていないためです（→ [7章](#7-手順地図タイルのダウンロード領域の公開)）。

### 10.2 E03（データ不備）の代表例と直し方

E03 は**トークンではなくデータの中身**の問題です。画面の「理由:」を見て直します。

| 「理由」の表示 | 意味 | 直し方 |
|----------------|------|--------|
| …の座標が箕面エリアの範囲外です | 地点の座標が想定範囲外（経度 135.2〜135.8／緯度 34.6〜35.1） | **MapEditor で**該当地点を正しい位置に直し、出力し直す |
| id が重複しています: … | 同じ `id` の地点が複数ある | **MapEditor で**重複を解消して出力し直す（表示の「理由」に重複した `id` が出ます） |
| …が Feature 形式ではありません | データ構造が不正 | 読み込んだファイルを見直す（開発担当者へ連絡） |
| FeatureCollection 形式の geojson ではありません | ファイルの形式が違う | MapEditor で出力したファイルを選び直す |
| version は yyyy.nn 形式で指定してください | バージョンの形式が違う | 「公開バージョン」欄を `2026.01` の形にする（→ [8.4](#84-公開できない番号)） |
| version … はすでに公開されています | 同じ番号で公開しようとした | 「公開バージョン」欄の番号を進める（→ [8.4](#84-公開できない番号)） |

> **直すのは MapEditor 側です。** このアプリには編集機能がありません。

## 11. 付録: 公開トークンの決め方と Vercel 設定（設定担当者向け）

> この章は **設定担当者（開発担当）向け**です。日常の公開を行う運用担当者は不要です。
> 作業は原則 **初回に一度だけ**（＋ローテーション時）です。

### 11.1 公開トークンの決め方

このトークン1個で公開データの全置換（偽情報の掲載・0件公開による全消去）ができるため、
**最重要の秘密**として扱います。意味のある文字列ではなく**暗号的にランダムな値**を使います。

| 条件 | 内容 |
|------|------|
| 長くランダム | 32 バイト（16進で64文字）程度。単語・日付・アプリ名は使わない |
| 埋め込まない | コードや git に入れない。Vercel の環境変数と、担当者のパスワードマネージャーだけに保存 |
| 交換できる | 漏洩が疑われたら値を更新して無効化できる（→ [11.3](#113-トークンのローテーション更新)） |

**生成コマンド（Windows PowerShell）** — `Get-Random` は暗号用途に不適なので使いません:

```powershell
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
-join ($bytes | ForEach-Object { '{0:x2}' -f $_ })
```

### 11.2 Vercel での設定

必要なのは **(A) Blob ストア接続** と **(B) 環境変数 `MAP_PUBLISH_TOKEN`** の2つです。
いずれも公開先の minoh-hiking プロジェクト側の設定です。

**(A) Blob ストアをプロジェクトに接続（初回のみ）**
公開データの保存に使う `BLOB_READ_WRITE_TOKEN` が**自動で**環境変数に追加されます。

1. Vercel ダッシュボード → 対象プロジェクト → 上部タブ **Storage**
2. **Create Database**（既存があれば選択）→ **Blob** → 作成して対象プロジェクトへ **Connect**
3. Settings → Environment Variables に `BLOB_READ_WRITE_TOKEN` が入っていることを確認

**(B) 環境変数 `MAP_PUBLISH_TOKEN` を設定**

1. プロジェクト → **Settings** → **Environment Variables** → **Add New**
2. **Key**: `MAP_PUBLISH_TOKEN` ／ **Value**: 11.1 で生成した値 ／
   **Environment**: **Production**（「Sensitive」にできる場合はオンにする）
3. **Save**

> **設定はコードのデプロイより先に行ってください。** 未設定のままデプロイすると
> すべての公開が E02 になります。

**(C) 反映（再デプロイ）**
環境変数は**追加後の新しいデプロイから有効**です。
**Deployments → 最新デプロイの ⋯ → Redeploy** を実行し、**Ready（緑）** を待ちます。

**動作確認**

| 状態 | 挙動 |
|------|------|
| トークン未設定のまま「公開」 | `503` → 画面では **E02** |
| 間違ったトークンで「公開」 | `401` → 画面では **E01** |
| 正しいトークンで「公開」 | `200` 成功（初回のみ端末でトークン入力） |

### 11.3 トークンのローテーション（更新）

**流れ**: ① 新しい値を生成 → ② Vercel の環境変数を上書き → ③ 再デプロイ → ④ 各運用端末で再入力。

1. [11.1](#111-公開トークンの決め方) のコマンドで新しい値を作り、パスワードマネージャーに保存します。
2. **Settings → Environment Variables** で `MAP_PUBLISH_TOKEN` の行の
   **右端「⋯」→ Edit**（新規の "Add New" ではありません）。**Value** を新しい値に置き換えて **Save**。
   - Sensitive 設定のため**現在の値は表示されません**（仕様）。古い値を確認する必要はなく、
     新しい値で上書きするだけで更新できます。
3. **Deployments → 最新デプロイの ⋯ → Redeploy** で反映し、**Ready** を待ちます。
4. 各運用端末では、更新後の初回「公開」時に新しいトークンの入力を求められます。
   古い値のままだと E01 になり、その端末の保存値は自動で消去されます。
   - トークンが端末に保存されるのは**公開が成功したときだけ**です。

> `BLOB_READ_WRITE_TOKEN` は公開画面で入力するものではなく、サーバーが Blob へ書き込む鍵です。
> 手動編集せず、**Storage タブ**の Blob ストア側で再発行・管理します（反映には再デプロイが必要）。

## 12. うまくいかないとき

| 症状 | 原因・対処 |
|------|------------|
| 地点を動かしたい・名前を直したい | **このアプリではできません。** MapEditor で直して出力し直す |
| 別のセクションを開いたら前のセクションが閉じた | 仕様です。開くのは常に1つだけです。閉じても読み込んだデータは消えません（「現在公開中」は見出しに出たままです） |
| 公開に失敗したら読み込んだデータが消えた | 仕様です。画面は公開中の状態に戻ります（→ [10.0](#100-失敗すると画面は公開中の状態に戻ります)）。ファイルを読み込み直してやり直してください |
| 「公開」を押しても確認画面が出ない | 「公開バージョン」欄を確認してください。形式違い・現在公開中と同じ番号のときは、画面下部にメッセージが出て止まります（→ [8.4](#84-公開できない番号)） |
| 「公開バージョン」欄が空のまま | 「現在公開中」を取得できていません。**↻** で取り直すか、`2026.01` の形で手入力してください |
| 書き換えたバージョンが元に戻ってしまう | 公開に成功したあとは、次の番号が自動で入ります（仕様です）。↻ では戻りません |
| 「公開済みデータを出力」の中身が、読み込んだファイルと違う | 仕様です。このボタンは**いま公開されている内容**を保存します。読み込んだファイルの控えではありません |
| 出力したファイルを MapEditor で開いても編集できない | 公開データには編集用の情報（スポットの id など）が入っていません。編集は MapEditor 側の元ファイルで行ってください |
| 読み込んだら前のデータが消えた | 仕様です。読み込みは**置換**です。両方公開したい場合は、MapEditor で1つのファイルにまとめる |
| 「公開対象外 … は公開しません」と出る | 正常です。利用者アプリで使わない種別（エリアなど）は公開しません。心当たりのない種別なら、読み込むファイルを間違えていないか確認してください |
| 「現在公開中」が「取得できません」になる | 通信状況を確認し **↻** で再取得。取得できなくても公開自体は行えます。ただし**地図タイルは公開先が未準備のため、常に「取得できません」**です |
| ルート線が端のスポットまで繋がらない | MapEditor 側で端点の座標が入っていない可能性があります。MapEditor で確認してください |
| 「読み込みエラー: FeatureCollection 形式の geojson ではありません」 | ファイルの形式が違います。MapEditor が出力したファイルを選ぶ |
| 読み込んでも「見つかりませんでした」 | セクションを間違えている可能性があります（3つのデータはそれぞれ別のセクションで読み込みます） |
| 区分が勝手に「通行止め」になった | MapEditor 側で区分が未設定の地点です。警告に件数が出ます。MapEditor で設定して出力し直す |
| 公開したのにユーザー側で変わらない | 端末が**まだマップを開き直していない**。開き直すと反映されます |
| 「公開に失敗しました」（E01〜E06） | メッセージ先頭の**エラーコードで対応が決まる** → [10章](#10-公開に失敗したときの対応エラーコード別) |
