## 1. はじめに

### 1.1 GeoReferencerとは
GeoReferencerは、PNG形式のハイキングマップや登山地図などの画像を、国土地理院の地形図上に正確に重ね合わせるWebアプリケーションです。画像内の主要ポイント、ルート、スポット、エリア（多角形領域）の情報をGPS座標に変換し、GeoJSON形式でエクスポートして他のGISソフトで利用できます。

**v2.0でクラウド（Firebase）依存を撤廃し、完全にローカル環境でデータを扱えます。v2.1ではエリア（多角形）の取り扱いと標高取得対象の追加、複合JSON形式（1ファイルにポイント・ルート・スポット・エリアをまとめた形式）の正式対応など、機能を強化しています。**

### 1.2 主な用途
- ハイキングマップ・登山地図のデジタル化
- 画像地図のGPS座標変換
- ルート・スポット・エリア情報のGeoJSON化
- 標高データの取得・付与（4種別の対象から選択可能）

### 1.3 必要なもの
- **Webブラウザ**: Chrome、Edge、Firefox、Safari等のES6モジュール対応ブラウザ
  - 推奨: Chrome／Edge（File System Access API対応で保存ダイアログが使えます）
- **入力ファイル**:
  - PNG画像ファイル（地図画像）
  - Excelファイル (.xlsx) — 基準となるGPS座標データ
  - （任意）JSONファイル — 画像上のポイント・ルート・スポット・エリア定義

### 1.4 できること・できないこと

#### できること ✅
- PNG画像を地理院地図上に重ね合わせ（6パラメータアフィン変換）
- 画像内座標（ポイント／ルート／スポット／エリア）をGPS座標に変換
- 変換済みデータのGeoJSONエクスポート
- 国土地理院APIからの標高データ自動取得（4種別を選択可能）
- 複数ファイルの追記読み込み（重複は自動スキップ）
- ローカル動作（通信は地図タイル・標高APIのみ）

#### できないこと ❌
- JPEG／GIF／SVG等のPNG以外の画像形式
- 複数人でのリアルタイム同時編集
- WGS84以外の座標系（JGD2011等）への変換出力

## 2. セットアップ

### 2.1 ローカルサーバーの起動
本アプリはES6モジュールを使用するため、ブラウザで直接ファイルを開くのではなく、ローカルサーバー経由でアクセスする必要があります。

#### Pythonを使う場合
```bash
cd /path/to/GeoReferencer
python -m http.server 8000
```

#### Node.jsを使う場合
```bash
npx serve .
```

### 2.2 ブラウザでアクセス
ローカルサーバー起動後、以下のURLにアクセスします。
```
http://localhost:8000
```
正常に起動すると、国土地理院の地形図（中心: 箕面大滝、ズーム15）が表示されます。

## 3. 画面構成

| エリア | 説明 |
|--------|------|
| 地図エリア | 画面全体に国土地理院地形図を表示 |
| 操作パネル | 読み込み／マッチング／標高／保存の各機能を配置 |
| メッセージエリア | 上部中央に成功・エラー・進捗メッセージを表示（3秒で消える） |
| ズームコントロール | 左上・右下の2か所 |
| スケールバー | 右下、メートル単位 |

### 3.1 操作パネルの主な要素
- **読み込み**: ラジオボタンで「ポイントGPS／PNG画像／JSONファイル」を選び、「読み込み」ボタンでファイル選択
- **件数表示**: GPSポイント、ポイント、ルート、スポット、エリアの個数を常時表示
- **画像の重ね合わせ（ジオリファレンス）**: マッチングと座標変換を実行
- **一致ポイント数 / 不一致ポイント**: マッチング結果
- **標高取得**: ポイント／ルート中間点／スポット／エリア頂点の標高を一括取得
- **変換後のGPS値をGeoJSONファイルに保存**: 結果をGeoJSONで保存

## 4. 基本操作（ワークフロー）

```
1. PNG画像を読み込む
2. ポイントGPSデータ（Excel）を読み込む
3. （任意）JSONデータ（ポイント／ルート／スポット／エリア）を読み込む
4. 「画像の重ね合わせ（ジオリファレンス）」を実行
5. （任意）標高取得
6. GeoJSONを保存
```

### 4.1 PNG画像を読み込む
1. ラジオボタンで「**PNG画像**」を選択
2. 「**読み込み**」ボタンをクリックしてPNGファイルを選択
3. 地図上に画像が半透明で表示されます
4. ファイル名がパネルに表示されます

> 注: 既に画像が読み込まれている状態で別の画像を読み込むと、ポイント・ルート・スポット・エリアなど関連データはすべてクリアされます（確認ダイアログあり）。

### 4.2 ポイントGPSを読み込む
1. ラジオボタンで「**ポイントGPS**」を選択
2. 「**読み込み**」ボタンをクリックしてExcelファイル（.xlsx）を選択
3. 緑色のマーカーが地図上に表示されます

複数ファイル選択や、追加の読み込みにも対応します（既存データがあれば追記／中止の確認が出ます）。

### 4.3 JSONデータを読み込む（任意）
1. **先にPNG画像を読み込んでおく必要があります**（未読込の場合は警告）
2. ラジオボタンで「**JSONファイル**」を選択
3. 「**読み込み**」ボタンをクリック（複数選択可能）
4. ファイル形式は自動判定されます（ポイント／ルート／スポット／エリア／複合形式）
5. 件数表示が更新され、画像上にマーカーが配置されます

> 既存JSONデータがある場合は「追記／中止」が確認されます。追記時、重複は座標やIDで自動判定しスキップします。

### 4.4 ジオリファレンスを実行
1. PNG画像とポイントGPS（または `id` 付きポイントJSON）が読み込まれた状態で「**画像の重ね合わせ（ジオリファレンス）**」をクリック
2. ID完全一致でマッチングが行われ、画像が地図に合わせて変形・移動します
3. 「一致ポイント数」「不一致ポイント」が表示されます
4. 完了後、「標高取得」と「GeoJSON保存」ボタンが有効化されます

> 必要な制御点数: 最低3点、推奨4点以上（多いほど精度向上）。

### 4.5 標高取得（任意）
1. 取得したい対象のチェックボックスをオン（ポイント／ルート中間点／スポット／エリア頂点）
2. 「**標高取得**」ボタンをクリック
3. 進捗バーで進捗を確認（0.5秒/件のレート制限）
4. 完了後、取得成功・失敗件数が表示されます
5. 標高未取得件数の表示が更新されます（既取得分はスキップ）

### 4.6 GeoJSONを保存
1. 「**変換後のGPS値をGeoJSONファイルに保存**」をクリック
2. ファイル保存ダイアログ（File System Access API対応ブラウザの場合）またはダウンロードでファイルが保存されます
3. デフォルトファイル名は `{画像名略称}-GPS-P{N}_R{N}_S{N}_A{N}-{YYYYMMDD}.geojson`
   - 例: `minoo-GPS-P5_R2_S3-20260427.geojson`
   - 件数0の項目は省略

## 5. 入力データの準備

### 5.1 Excel（ポイントGPS）
| 列名 | 必須 | 例 |
|------|------|-----|
| ポイントID | ○ | `A-01` |
| 名称 | ○ | 山頂A |
| 緯度 | ○ | `35.123456` |
| 経度 | ○ | `139.654321` |
| 標高 | - | `512` |
| 備考 | - | 任意の文字列 |

- 1ファイル最大1000行（ヘッダー含む）。
- 緯度は -90〜90、経度は -180〜180。

### 5.2 JSON（画像内座標定義）
詳細は `dataspec-json-202604.md` を参照。代表例を以下に示します。

#### ポイントJSON
```json
{
  "points": [
    { "id": "A-01", "name": "登山口", "imageX": 100, "imageY": 200 }
  ]
}
```

#### ルートJSON
```json
{
  "routeInfo": { "startPoint": "A-01", "endPoint": "A-02", "routeName": "表参道" },
  "points": [
    { "type": "waypoint", "imageX": 100, "imageY": 200 },
    { "type": "waypoint", "imageX": 150, "imageY": 250 }
  ]
}
```

#### スポットJSON
```json
{
  "spots": [
    { "name": "見晴台", "imageX": 300, "imageY": 400, "description": "絶景" }
  ]
}
```

#### エリアJSON
```json
{
  "areas": [
    {
      "id": "area_01",
      "name": "駐車場",
      "vertices": [
        { "x": 100, "y": 100 },
        { "x": 200, "y": 100 },
        { "x": 200, "y": 200 },
        { "x": 100, "y": 200 }
      ]
    }
  ]
}
```

#### 複合JSON（1ファイルにまとめる）
```json
{
  "version": "1.0",
  "imageReference": "minoo-trail-map.png",
  "data": {
    "points":  [ { "id": "A-01", "name": "登山口", "x": 100, "y": 200 } ],
    "routes":  [ { "routeName": "表参道", "startPoint": "A-01", "endPoint": "A-02",
                   "waypoints": [ { "x": 100, "y": 200 }, { "x": 150, "y": 250 } ] } ],
    "spots":   [ { "name": "見晴台", "x": 300, "y": 400 } ],
    "areas":   [ { "id": "area_01", "name": "駐車場",
                   "vertices": [ { "x": 100, "y": 100 }, { "x": 200, "y": 100 },
                                 { "x": 200, "y": 200 }, { "x": 100, "y": 200 } ] } ]
  }
}
```

> 画像座標フィールドは「`imageX/imageY`」を基本とし、複合形式とエリアでは「`x/y`」も使えます。エリアの `vertices` は `x/y` のみ。

## 6. 詳細機能

### 6.1 マーカーの種類
| 種別 | 表示 | 用途 |
|------|------|------|
| GPSポイント | 緑色円形 | Excel由来の基準点 |
| 画像内ポイント | 赤色円形 | JSON由来のポイント／pointJSON |
| ルート中間点 | オレンジ／ダイヤ | ルート上の通過点 |
| スポット | 青 | 見晴台、トイレ等 |
| エリア | ピンク多角形（HotPink境界＋LightPink塗30%） | 駐車場、危険地帯等 |
| エリア頂点 | ピンク菱形 (6px) | エリアの各頂点 |

### 6.2 自動JSON判定
読み込み時に下記の条件でファイル種別を自動判定します。

| 形式 | 判定条件 |
|------|----------|
| Combined | `data` オブジェクトに `points/routes/spots/areas` のいずれかが存在 |
| Route | `routeInfo.startPoint` + `routeInfo.endPoint` + `points[type="waypoint"]` |
| Spot | `spots[]` に `name` と `imageX/Y` があるもの、または同形式の単一オブジェクト |
| Point | `points[]` に `type !== "waypoint"` で `id` または `name` を持つもの |
| Area | `areas[].vertices[]` に `x/y` を持つもの |

### 6.3 重複・追記読み込み
- **GPSポイント**: 緯度・経度の許容誤差約 1e-7 度以内で重複と判定
- **ポイントJSON**: ID と座標の一致で重複判定
- **ルート**: 開始ID／終了IDの正方向・逆方向比較、または座標誤差0.0001度以内
- **スポット**: 画像座標の0.1ピクセル以内、またはGPS座標の0.0001度以内
- **エリア**: ID で識別

### 6.4 アフィン変換と精度
- **方式**: 6パラメータアフィン変換（平行移動・回転・スケール・剪断、Web Mercator経由）
- **最小制御点数**: 3点（推奨4点以上）
- **マッチング**: ポイントJSONの`id` ↔ Excelの「ポイントID」を完全一致
- **同期**: 変換後の画像位置変更に追従して、ポイント・ルート・スポット・エリアのマーカー位置が更新されます

### 6.5 標高取得
- 国土地理院標高APIを使用（0.5秒/件、小数点1桁）
- 4種類の対象（ポイント／ルート中間点／スポット／エリア頂点）から選択
- 既に標高が設定されている地点はスキップ
- 取得進捗はバーで表示、完了後3秒で非表示
- 取得値はメモリ上に保持され、GeoJSON出力時に第3座標として出力

### 6.6 ファイル保存（File System Access API）
- 対応ブラウザ: 保存ダイアログでフォルダ・ファイル名を指定可能。前回読み込んだフォルダから開始
- 未対応ブラウザ: ブラウザのダウンロード機能でフォールバック保存

## 7. 出力ファイル

### 7.1 GeoJSON出力概要
- フォーマット: GeoJSON (RFC 7946)、`FeatureCollection`
- 拡張子: `.geojson`
- 座標系: WGS84、`[lng, lat]` または `[lng, lat, elevation]`
- 数値: 経度・緯度・標高は小数点5桁で丸め

### 7.2 Feature種別
| `properties.type` | Geometry | 用途 |
|---|---|---|
| `point` | Point | 画像由来のポイント |
| `spot` | Point | スポット |
| `route` | LineString | ルート（中間点を順に結ぶ） |
| `area` | Polygon | エリア（自動閉合） |

ルートFeatureには `startPoint`、`endPoint`、`startPointGPS`、`endPointGPS` が付加されます。

### 7.3 ファイル名規則
```
{略称}-GPS-P{point数}_R{route数}_S{spot数}_A{area数}-{YYYYMMDD}.geojson
```
- 略称: PNG画像名先頭から区切り文字（`-`、`_`、` `、`.`）の前まで
- 件数0の項目は省略

例:
- `minoo-GPS-P5_R2_S3-20260427.geojson`
- `takao-GPS-P10_A1-20260427.geojson`

> 注: ポイントGPS（Excel由来）はGeoJSON出力対象外です。画像由来のデータをGPS変換した結果のみ出力されます。

## 8. トラブルシューティング

### 8.1 画像が表示されない
- PNG形式であることを確認してください。
- ファイルサイズが大きすぎる場合（数十MB以上）、ブラウザのメモリ制限にかかることがあります。
- ローカルサーバー経由でアクセスしているか確認してください（`file://` 直開きはNG）。

### 8.2 「JSONファイル」読み込みボタンを押しても反応しない
- 先にPNG画像を読み込む必要があります（警告ダイアログが出ます）。

### 8.3 ジオリファレンス時に「最低3つのポイントが必要です」と出る
- マッチした制御点が3点未満です。
- ExcelのポイントIDと、画像上（JSON）のIDが完全一致しているか確認してください（全角／半角、空白、大文字小文字）。
- ポイントJSONを読み込んでいるか確認してください。

### 8.4 標高取得が遅い／途中で止まる
- 国土地理院APIへの負荷を避けるため意図的に0.5秒/件の待機を入れています。
- ネットワーク接続と、APIの一時的な制限を確認してください。
- 失敗件数が多い場合は時間をおいて再実行してください。

### 8.5 エリアが表示されない
- ジオリファレンスが完了するまで、エリアは画像境界ベースで配置されます。ジオリファレンス後に正しい位置に再配置されます。
- `vertices` 配列が空、または `x/y` がない場合はスキップされます。

### 8.6 GeoJSON保存ボタンが押せない
- ジオリファレンスを実行すると有効化されます。
- 出力対象のFeatureが0件の場合（変換可能なポイント・ルート・スポット・エリアがない場合）はエラー表示されます。

## 9. よくある質問

**Q1. クラウドに保存されますか？**
A. いいえ。v2.0からクラウド保存機能は削除されました。すべてのデータはお使いのPC内に保存（ダウンロード）されます。

**Q2. オフラインで使えますか？**
A. 地図タイル（国土地理院）の表示と標高取得APIにはインターネット接続が必要です。アプリ自体はローカルサーバーで起動できます。

**Q3. 以前のFirebaseデータはどうなりますか？**
A. 本バージョンではFirebase連携機能が削除されているため、過去のクラウドデータは読み込めません。旧バージョンでエクスポートしてから移行してください。

**Q4. 1ファイルにポイント・ルート・スポット・エリアをまとめられますか？**
A. はい。複合JSON形式（`data` ラッパー）として読み込み・保存できます（5.2節 / `dataspec-json-202604.md` 参照）。

**Q5. 標高は何メートル単位で取得できますか？**
A. 国土地理院標高APIから取得し、小数点1桁で丸めた値（メートル単位）を保持します。GeoJSON出力時は他の座標と同様に小数点5桁丸めの値で第3座標として書き出されます。

**Q6. 出力したGeoJSONを別のGISで使いたい**
A. RFC 7946準拠なので、QGIS、ArcGIS、Mapbox等の主要なGISソフトでそのまま読み込めます。座標系はWGS84（EPSG:4326）です。

**Q7. ルートの開始／終了ポイントのGPS値はどう決まりますか？**
A. 同一GeoJSON内のポイント／スポットFeatureから `id` または `name` でルックアップします。見つからない場合は `routeData.startPoint` / `endPoint` の `lat/lng` を使用し、それも無ければ `null` になります。
